# M11 — Main menu and pause flow

The project now starts at GameSession's [main menu](M11/menu.png). New Game
instantiates the actual bunker once. The gameplay subtree is explicitly
PAUSABLE while menu/input handling remains ALWAYS, so Escape can resume it.

Live MCP verification:

- A transformed mouse click on New Game creates the bunker and enters WALK.
- Physical Escape opens [pause](M11/pause.png). Physics ticks remain at 1,071
  before/after a 0.25s real-time observation while the menu continues rendering.
- Escape resumes, advances physics, and retains the same world instance.
- Return to Main Menu removes the world, leaves the tree unpaused, releases
  the pointer into MENU context and displays the main menu again.
- Live editor/game logs report no errors, including world teardown.

17 GUT tests / 82 assertions pass in 25.307 seconds. Additional coverage checks
that TERMINAL context continues simulation instead of pausing it. Existing
interaction, collision, camera and airlock tests remain green.

Main and pause screens share MenuFlow instead of duplicating scene layouts.
Continue/save controls are added in M12 once persistence exists. Export probe
arguments start a world automatically, preserving the existing runtime check.
