# M10 — Tactile station interactions

E activates the aimed physical control within 2m, using the first collision hit.
The ray is queried again at use time, preventing stale focus from bypassing
distance or walls. World interaction stops in terminal/menu context.

Live MCP checks:

- [Command desk](M10/command.png), [workshop](M10/workshop.png),
  [life-support panel](M10/life.png) open through their actual prop colliders.
- Injected E opens a panel; physical Escape closes it and returns to WALK.
- A mouse click transformed through the 3× viewport presses the power button;
  [panel power off](M10/power_off.png) also hides that physical CRT's text.
- Command light switch returns used=true and light.visible=false;
  [room switch](M10/switch.png) shows the darkened room next to the lit workshop.
- [Inner airlock control](M10/airlock.png) remains fixed when the door slides away.
  Live target path is Bunker/AirlockControlOutside/Interaction. Opening completes;
  placing the operator in the aperture makes request_close return false.

15 GUT tests / 72 assertions pass in 24.843 seconds. Tests cover use/exit input
boundaries, out-of-range and through-wall rejection, real light changes, access
to the inside airlock control, and occupied closing-sweep rejection. The first
airlock test pose overlapped the passage wall; corrected to a legal standing
position before the passing run.

Panels provide their purpose and local power state. Fleet telemetry, fabrication
and life-support simulation arrive in their planned milestones; no fake resource
readings are presented. CRT text is live UI geometry, not a generated texture file.
Additional wall controls reuse the already verified PSX lightSwitch asset.

Implementation uses shared interaction/panel components with authored bindings
in station_controller.gd instead of three duplicate station scenes. This keeps
later functional panels separate from range/input handling.
